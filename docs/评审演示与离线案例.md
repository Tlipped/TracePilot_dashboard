# 评审演示与离线案例

## 目标

比赛录屏需要稳定、可复现且主次明确。示例案例入口不得隐式创建长周期 Agent 任务，评审页面也不应暴露运行日志、侧栏和开发期指标。

## 页面行为

- 主页 SushiSwap 与 ApeCoin 快捷卡优先打开 `demo-sushiswap`、`demo-apecoin` 两个只读快照。
- 快捷卡不再调用 `createTask`；新任务只能通过“开始分析”或“已发生案例复盘”中的显式启动操作创建。
- 离线快照包含任务、结构化评审、宏观分析、自动评审、分页日志、部分完整日志和智能体文件，不依赖 Docker、WebSocket 或模型服务。
- 评审模式在结构化评审加载完成后提供“演示视图”按钮。

## 四步演示路径

1. 案件概览：一句话结论、攻击交易、步骤数、证据数和修复状态。
2. 攻击链：优先使用后端 `CaseReview.attack_stages`；旧快照缺少该字段时，从本案最终报告动态提取，不套用固定步骤。
3. 根因定位：只展示结构化根因结论及证据关联数量。
4. 修复验证：集中展示编译、攻击重放、攻击阻断和修复后收益。

演示视图隐藏任务进度、智能体导航、右侧详情、日志入口和取证助手，退出演示后恢复完整工作台。

## 固化案例

- SushiSwap：源任务 `6a5836c1-6122-47f3-9d70-2ba6d0f8a5d1`。
- ApeCoin：源任务 `a33fe665-bf56-409b-941b-3f8d51310828`。

快照由 `npm run demo:import` 从已完成任务生成，不会重新运行分析链路。提交前需要执行敏感信息扫描、`npm run test:demo-importer`、`npm run test:smoke`、`npm run lint` 和 `npm run build`。

两份比赛快照的概览、攻击步骤讲解和首要根因使用案例库中的中文可信摘要。步骤数量和顺序仍取自各自最终报告，只有提取结果与该案例的讲解文案完全匹配时才替换展示文本。原始英文模型报告仍保留在完整报告与原始日志中，避免演示页直接渲染长表格或未经整理的英文段落。
