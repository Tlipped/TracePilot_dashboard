# 结构化执行链前端接入说明

## 本次目标

工作台新增“执行链”视图，用结构化事件说明 Agent 如何完成分析，而不是继续堆叠模型对话日志。原始日志、智能体时间线和既有报告入口全部保留。

## 信息层级

默认“主流程”只展示：

1. 整个案件分析工作流；
2. 宏观筛选、任务规划、Trace 调试、补丁生成、补丁验证和报告等真实阶段；
3. Agent 之间的结构化交接。

每次交接直接说明来源 Agent、接收 Agent、交接原因、交付结论、下一步和产物。用户可以切换到“工具调用”查看 Trace 工具及其父模型轮次，也可以切换到“全部步骤”查看原有结构化模型日志；既有能力没有删除。列表只读取预览字段，点击步骤后才请求完整输入和输出，避免长载荷拖慢工作台。

每个步骤可确认：

- Agent 与分析阶段；
- 事件类型与具体操作；
- `parent_event_id` 表达的父子关系；
- 模型工具 `call_id` 对应的 `correlation_id`；
- 状态、耗时、证据引用；
- 脱敏后输出大小与 SHA-256；
- 完整调用参数和工具返回。

## 类型化结果

`get_node_detailed_state` 不按普通 JSON 文本处理。详情抽屉会直接渲染：

- Trace 节点、函数、逻辑合约与存储上下文；
- 解码输入输出、调用方变量和函数变量；
- SLOAD/SSTORE、变化前后值与源码行；
- EVM 事件。

完整事件 JSON 仍保留在折叠区域，便于专家复制和审计。其他尚未类型化的工具使用通用 JSON 查看器降级展示。

## 兼容策略

- 新任务从 `/api/tasks/{task_id}/execution-events` 获取真实执行事件。
- 旧任务不会补造顶层编排事件；主流程为空时明确提示切换到工具调用或全部步骤。
- 旧任务没有事件时明确提示“采集上线前任务”，不解析旧日志来伪造调用关系。
- 运行中任务每 4 秒静默刷新；完成任务只在进入页面时读取。
- 左侧智能体筛选同时作用于执行链。
- 深色、浅色和窄屏样式沿用现有工作台变量与断点。
